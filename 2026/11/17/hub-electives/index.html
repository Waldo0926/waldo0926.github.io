Finding electives on Monash Hub

Filter free electives by exam, prerequisites and campus. There is no final exam filter because the data can't support it.

17 Nov 2026 3 min read English 中文

Choosing a free elective comes down to three questions that I get asked every semester: does it have an exam, does it need a prerequisite, and is it taught at my campus. Monash Hub could already filter the unit list on all three, but nobody finds a filter they do not know exists. So there is now a page for electives that links straight into the list with those filters set.

What the page does

There are four conditions at the top: no exam listed, no prerequisite listed, both together, and level 1 units with no prerequisite listed. Each shows how many units fit. Pick one and the page lists 12 undergraduate units that fit, with a button to the full unit list with the filters already set. A campus switch (Malaysia or Australia) follows the same cookie as the home page.

The 12 units take turns between faculties. In code order the first dozen were all accounting units starting with ACB or ACM, so the API got a sort=mixed option: the lowest-level unit of each faculty first, then the next of each. The first version also had a list grouped by faculty. I removed it, because the Handbook’s faculty field mixes faculties with departments and the list looked messy.

The page never says a unit is easy and never recommends one. Whether a unit counts as a free elective depends on the course, so the page says to check the course page or the progression map, and ask the faculty when unsure.

What “no prerequisite” means

The no_prereq filter keeps the units that have no prerequisite group in the Handbook data. It means the Handbook lists none. An entry requirement written only in the unit’s description text is not a prerequisite group, so it can still exist. The page says this next to the filter, because “not listed” is not the same as “none”.

Why there is no final exam filter

Students often ask for units with no final exam, and I wanted to add that filter. Then I looked at the data. The exam filter works from assessment names that contain “exam” or “examination”. In a sample of 120 live units I found 55 such items. Only 3 were named final and 1 was named mid. The other 51 were just called “Examination”.

So the Handbook data cannot tell a final exam from a midterm, and a filter that claimed to would be guessing. I kept one filter, “no exam listed”, and the page says that final and midterm exams both count as exams, while quizzes and tests do not. A student who wants to avoid a final still needs to open the unit and read the assessment table.

I also got this wrong once. My first wording on the page and in the bot said units with “no final exam”, which the filter does not know. I changed it to “no exam listed” in #291.

How the bot sends people there

In qa/hub-topics.json there are four answers for the bot. When someone asks about electives, units without an exam, units without a prerequisite, or what is taught in a semester, it replies with the electives page and the unit list link with the filter set, for the Malaysia campus, plus a line on how to switch campus. If someone asks for “no final exam”, the answer says one filter exists, for no exam listed, and explains what that covers. The answers have to be imported on the server before the bot uses them.
