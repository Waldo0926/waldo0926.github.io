微信机器人接入 Monash Hub

马莫百科的机器人现在也在 Monash Hub 的提问面板里回答，网站访客看不到只适用于公众号的内容

19 Nov 2026 约 3 分钟 English 中文

· 资料核对：2026-11-19

马莫百科的微信机器人回答 Monash 马来西亚校区学生和家长的问题，它知道的东西来自两处：只能逐字引用的官方页面，还有我在聊天里教它的回答

Monash Hub 自己也有一个提问面板，就是右下角那个圆按钮，它完全不用模型，只是把问题导到 Hub 上对应的页面、课程或重要日期

问“第一学期什么时候开学”“FIT2102 怎么样”它很擅长，但图书馆怎么打印、学生签证怎么办，它一概不知道，而这些机器人早就答得不错了

所以现在提问面板两边都问

面板怎么用这两个答案

你问一个问题，页面会同时发给 Hub 自己的路由和机器人，等两边都回来

机器人引用官方页面时可能要几秒，慢了或者挂了，它那部分就不显示，其他照常出来

  • 机器人的回答只是指回 Hub 的话就不显示，因为面板上已经有那个页面了
  • 机器人有自己的回答，就放在单独一个气泡里，标明是机器人答的
  • 打招呼或者问“你是谁”，只回一段简短介绍，什么都不搜

网站访客不是公众号粉丝

机器人跑在另一台服务器上，所以 Hub 调用它新加的 POST /web/ask，带一个共享密钥，没设密钥的话这个接口根本不存在

有些话只在微信里说得通，比如「回复人工」或者“在 Monash Hub 上查看更多”，网页上的回答会把它们去掉

更大的区别是答不上来的时候

在微信里，机器人答不上的正经问题会转给我，从网站来的不会转，因为我没法回复一个匿名的浏览器，转过来只会多一堆永远等不到回答的消息

所以面板会请访客去公众号问，那里我能回复

每个浏览器有一个随机 id，机器人按这个 id 限流，和限制微信用户一样，另外 Hub 每个地址每小时最多问机器人 60 次，网页上的回答超过 12 秒机器人就放弃，机器人日志里访客记成 web: 加上这个随机 id 的哈希

部署时有个细节比想象中费时间：Hub 的 API 跑在容器里，机器人监听的是宿主机的 loopback 地址，容器访问不到，最后是在宿主机的 nginx 上给 /web/ask 加了一条转发，步骤写在运维手册里

进群的小修复

这周另一个改动在私聊里

有人加了 MonashGuide 的微信，私聊说想进学生群，这个号本来就是拉人进群的号，但机器人回的却是公众号那段话，叫人去加 MonashGuide 好友，可他们已经加了

现在只在私聊里，像“进群”“能拉我进群吗”“群二维码过期了”这种短句，会回「请稍等，Waldo 看到后会邀请你进群～」，同时给我发一条提醒说谁想进群，同一个人一天最多提醒一次

比较长、只是顺带提到群的问题照常回答，公众号和群聊里的行为都没变
