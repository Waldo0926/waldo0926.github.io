Monash 在 [program search](https://www.monash.edu/study-abroad/outbound/program-search) 上列出了所有学期交换的合作学校，每个项目写着开没开放、几个名额、分数线，还有一个可申请程度的颜色

但页面不会告诉你上周写的是什么，我开始规划自己交换的时候，一直在问：“这所是刚关的，还是一直这样？”

所以从八月开始，有一个 tracker 每天晚上把整个名单读一遍，把变化记下来，线上数据和爬虫是私有的，[公开 demo](https://waldo0926.github.io/monash-abroad-tracker-demo/) 用虚构数据展示了同一个查看页面，设计思路写在[它的 README](https://github.com/Waldo0926/monash-abroad-tracker-demo) 里

## 不打扰对方网站

代码里没有写死任何学校名单，每次先读搜索页，留下类型是 Semester exchange 的卡片（大约 164 个），再逐个打开详情页

一次只发一个请求，每次运行都实时读 `robots.txt`，遵守里面的 `Crawl-delay: 30`，就算读不到这个文件也至少隔 30 秒，所以跑完一轮要 85 分钟左右，一天只跑一次，慢一点没关系

对方网站不是自己能控制的，总会出问题，所以规则定得比较保守：

- 某个详情页抓失败，这个项目保留上次的数据，超时不等于被删了
- 搜索页抓失败，整轮直接停下，数据一点不动
- 项目数量比上次少了 20% 以上，触发安全阀，什么都不写

## 留着页面原话

每个字段存两份：页面上的原文和整理后的值，比如 `OPEN.` 变成 `Open`，`60% WAM` 变成 `60.0` 和 `WAM`

这样查看页面说某个分数线涨了，我永远可以回去看 Monash 当时的原话是什么

只有真的有变化，才会写一个新的快照文件，同一天再跑一次什么都不会多

## 和上一轮比，而不是和昨天比

一开始是和昨天比，结果发现没什么用，大部分日子什么都没变，“变化”那一列总是空的，同学们真正想知道的是：这一轮和上一轮申请季比有什么不同

所以上一轮被冻结成基准放在仓库里，对比表每次都只用两样东西重新算：基准和今天的数据，从来不在原表上改，所以错的一行不会留到第二天

名额变少、分数线变高算更难，名额变多、重新开放算利好

一轮申请截止后，最后一份数据会单独归档：原始 JSON 和 CSV 一个字节不改，一份大家可以自己筛选的 Excel，这次运行的开始和结束时间，还有 SHA-256 校验值，这份归档可以直接当下一轮的基准

## 为什么放在家里跑

GitHub 托管的 runner 访问 Monash 网站会被直接返回 HTTP 403，所以爬虫放在家里一台 Debian 小主机上，用 systemd timer 定时跑

每天晚上 19:00 跑一次，因为对方是上班时间改数据，每两小时有一次补跑，只有上次定时抓取已经超过 20 小时才会真的去抓，手动跑的那次不算当晚那一次

无人值守跑了一段时间，发现了一些平时根本发现不了的 bug：

- 生成的数据文件里混进了 git 冲突标记，因为脚本是先抓取再 pull，现在改成先同步再抓取，有冲突就绝不提交
- 一轮要跑 90 分钟，这期间别的地方写进数据的东西，会被这轮结束时保存的那份覆盖掉
- 在 `set -o pipefail` 下，`git log | grep -q` 有时会被当成失败：grep 一匹配到就退出，git 收到 SIGPIPE 以 141 结束，整条管道就算失败了，结果“今天已经抓过”时灵时不灵，网站被抓了两遍
- 更早的时候用 macOS 的 launchd 定时，但一次都没跑过，因为脚本放在桌面文件夹里，被 macOS 的隐私保护挡住了

现在每次更新数据，在发布之前都会先检查一遍：字段结构、每个项目网址只有一条记录，还有 JSON 和 CSV 两份内容一致，以前只改数据的提交会跳过 CI，所以这个检查直接放在更新流程里

## 数据说明不了的事

一直盯着这份名单，让我在规划自己选课的时候更明白一件事：课名相似只是搜索线索，不代表能转学分

真正决定的是课程大纲、考核方式、学分、课程级别，以及你在那边的那个学期这门课到底开不开，如果这门课只在另一个学期开，内容对得再好也用不上

我也会把三种匹配分开看：从公开信息看起来对得上的、学院讨论过的、有书面批准的，合作学校改了开课安排，以前的对应关系也要重新核对

tracker 能告诉你某个项目什么时候开放、关闭或者变难了，至于那边的课能不能算进你的学位，还是要问自己的学院
